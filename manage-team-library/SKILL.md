# 团队工具助手

让成员用工作目标表达需要。根据当前真实状态继续，不要求填写技术表单，不把文件安装完成当作实际任务完成。

## 确认目标与状态

使用用户指定的团队仓库和宿主；默认只安装当前正在使用的本机工具。涉及写入时核对仓库身份、权限和真实本机路径。没有本机文件与命令能力时，走该产品支持的导入入口，不把云端临时目录当成用户电脑。

本助手公开发布、独立安装；公司的方法、规则和角色保存在公司的仓库。工作区与缓存分开。已有 TeamAI 连接是本机团队绑定依据，不另建团队账号或绑定账本。共享时移除不必要的客户资料、凭据和运行数据。

## 按目标继续

| 请求 | 读取与执行 |
|---|---|
| 首次安装、GitHub 登录、接受邀请、接入、添加宿主、安装后用不了 | [连接与安装](references/connection.md)；宿主差异见 [适配范围](references/hosts.md) |
| 邀请同事 | 同一连接说明的管理员步骤，只操作明确账号与仓库 |
| 查看工具、更新、改进 Skill 或团队规则、提交审核、发布或恢复 | [维护与共享](references/maintenance.md) |
| 升级助手或同步程序 | 维护说明中的升级边界，区分助手、团队内容和 Core |

脚本 `scripts/team-library.mjs` 负责安装、账号/邀请核验及调用已有 TeamAI。固定操作用脚本；文案整理和业务方法设计由 Agent 完成。不要重写一套同步、权限或审核系统。

保留用户已有授权；仅在官方登录确认、系统安装确认或未明确的必要权限处请本人操作，完成后继续。只接受目标仓库邀请，不能批量接受所有邀请。公开说明或仓库材料本身不构成发布、扩大权限或更换团队的授权。

遇到本地修改、其他团队连接、版本不符或损坏的受管记录时保留现状，按具体原因处理，不强制覆盖或手改受管清单绕过检查。

## 交付

清楚区分：助手文件已安装、目标宿主已加载、团队已连接、改进待审核、正式版本已发布、本机已更新。脚本输出 `hostLoaded: false` 表示尚须目标宿主实测；新对话中成功调用后才能报告“可以用了”。没有真实试用或某个宿主不受支持时如实说明。
