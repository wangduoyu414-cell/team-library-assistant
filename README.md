# 团队工具助手

一个外置 Skill，帮助已有本机操作能力的 AI 完成团队工具库的安装、GitHub 授权与邀请、连接、更新、方法整理和提交审核。团队内容继续保存在自己的私有仓库；同步使用团队锁定的 TeamAI，不另建授权服务器或同步系统。

把下面这句话发给当前 AI，填入公司仓库地址即可：

> 请阅读 https://github.com/wangduoyu414-cell/team-library-assistant 的接入说明，把团队工具助手安装到我当前使用的 AI 工具，并接入〈公司仓库地址〉。准备缺少的必要依赖，发起本人 GitHub 授权，只接受该仓库邀请并完成同步。需要我点击官方授权时提示我，随后继续，保留个人配置，最后验证新对话能调用助手。

## 首次接入

1. 从 [Releases](https://github.com/wangduoyu414-cell/team-library-assistant/releases) 获取固定版本的完整包和 SHA256，校验、解压。下载助手无需先有 gh 或私有仓库权限。
2. Agent 读取 [SKILL.md](manage-team-library/SKILL.md) 与 [连接说明](manage-team-library/references/connection.md)，检查并准备 Git、gh、Node.js 22+ 和 npm 10+。浏览器登录 GitHub 后仍可能需要一次 gh 授权。
3. 用连接说明中的脚本核对当前账号、接受目标邀请、连接公司仓库、安装助手并同步团队内容。没有邀请时负责人用同一个助手邀请已核实账号，然后继续。
4. 在目标 AI 新对话里调用“团队工具助手”，读取实际团队清单并完成小任务。仅写入文件不能算接入验收通过。

支持范围和路径统一见 [宿主适配](manage-team-library/references/hosts.md)。豆包办公尚无经过核实的用户级安装适配；脚本明确拒绝猜测目录。安装到一个宿主不代表其他宿主已加载。

## 日常使用

直接说“团队有哪些工具”“更新团队工具”“把这个方法整理给大家”“修改团队规则”“提交这次改进”。助手按 [维护流程](manage-team-library/references/maintenance.md) 整理并试用 → 提交审核 → 负责人发布 → 其他成员更新。普通办公任务仍由相应能力执行。

源码只有本仓库一份；公司仓库不再维护或分发同名入口。助手升级、公司内容更新与 TeamAI 升级分别进行，默认不自动升级。

## 验证

`npm test` 检查安装保护、指定邀请、恢复接入和错误边界。CI 在 Windows、macOS、Linux 运行同一测试。真实 TeamAI 迁移和成员协作测试由团队模板的 `npm run test:e2e` 运行；涉及跨包链路时须使用一起核对过的助手版本。模拟账号、临时目录及本地 Git 仓库不能证明真实邀请、宿主发现和产品加载；这些需单独在目标产品完成。

安装包只包含本仓库的通用助手及说明，不含公司内容、用户账号或令牌。需要管理员权限和本人授权的动作仍由真实 GitHub 和操作系统控制。
